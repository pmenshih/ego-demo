# Лабораторная 2 · Трансформер руками: токены, векторы, внимание

**Лекция:** 2 · **Сдача:** папка `lab02/` в вашем репозитории: `run.py`, артефакты в `artifacts/`, README из трех разделов по регламенту; ноутбук по желанию · **Проверка:** автотесты в CI плюс выборочно устно · **Дедлайн:** по регламенту лабораторных, мягкий на следующем занятии по лабораторным.

## Задача

На лекции трансформер был разобран по частям: текст режется на токены, токены превращаются в векторы, внимание смешивает векторы с учетом контекста. В этой работе с каждой частью вы взаимодействуете самостоятельно. Своя реализация только у токенизатора: BPE достаточно прост и, в тоже время, достаточно важен, чтобы один раз написать самостоятельно. Остальное берется из готовых моделей, вы их не обучаете, но заглядываете внутрь.

Основная модель та же, что в демо на лекциях: `Qwen/Qwen3-0.6B-Base`, полтора гигабайта, работает на CPU. В третьей части к ней добавляется маленький энкодер для поиска `intfloat/multilingual-e5-small`. Корпус фиксирован, чтобы результаты у всех были сравнимы: «Война и мир», текст по ссылке `https://raw.githubusercontent.com/nevmenandr/word2vec-russian-novels/master/books_before/WarAndPeace.txt`. Скрипт скачивает его сам, в репозиторий корпус не кладется.

## Для курсовой

Курсовая это сервис вокруг языковой модели, и три части этой работы являются её частью. Функция подсчета токенов из части 2 нужна, чтобы считать расход и укладываться в контекст. Поиск по абзацам из части 3 это ядро retrieval: тот самый `search(query, k)`, вокруг которого строится RAG. Кривая размывания из части 4 отвечает на вопрос, сколько найденных фрагментов класть в промпт. Пишите эти функции так, чтобы их можно было импортировать: следующие работы будут на них опираться.

## Что сделать

Все части выполняет один скрипт `lab02/run.py`, он пишет результаты в `lab02/artifacts/`. Имена и схема файлов ниже заданы жестко, их читают тесты. Внутри скрипта свобода полная.

1. **Свой BPE.** Привести корпус к нижнему регистру, заменить «ё» на «е», выделить слова регулярным выражением `[а-я]+(?:-[а-я]+)*`. Каждое слово разбить на буквы и добавить маркер конца слова `</w>`. Дальше классический алгоритм: найти самую частую пару соседних символов во всем словаре, слить ее в один символ, повторить. Слова с частотой ниже порога в обучение не брать, так быстрее. Полный режим: не меньше 1500 слияний; режим `--fast`: не меньше 200. Применить выученные слияния ко всему корпусу и посчитать, во сколько раз токенов меньше, чем букв. Записать `bpe.json`.

2. **Токенизатор настоящей модели и бюджет контекста.** Взять токенизатор Qwen3 через `transformers` и оформить функцию `count_tokens(text)`. Токенизировать абзац из корпуса (сто слов, слова с 500 по 600 по счету) и английский абзац ниже, сравнить число токенов на слово. Из этого посчитать, сколько слов русского и английского текста помещается в контекст из 4096 токенов. Английский абзац взять ровно этот, тесты сверяют число его токенов с токенизатором Qwen3:

   > The prince had been talking for almost an hour, and the guests were growing tired. Anna looked at the clock, then at the window, then at the clock again. Nobody dared to leave before the host, and the host did not seem to notice the time at all. A servant brought tea, and the conversation turned, as it always did in that house, to the war and to the emperor.

   Записать `tokens_per_word.json`. В README одна фраза: почему русский текст стоит дороже и что это означает для промпта с документами.

3. **Векторы и поиск по корпусу.** Разбить корпус на абзацы по переводам строки, оставить абзацы длиной от 40 до 120 слов (слова считать тем же регулярным выражением по тексту в нижнем регистре, сами абзацы хранить как есть), взять первые 500; в режиме `--fast` первые 60. Для каждого абзаца и для каждого запроса из таблицы ниже получить вектор тремя способами и для каждого способа найти пять ближайших абзацев по косинусу:

   - *static*: среднее векторов входных эмбеддингов Qwen3 по токенам текста. Контекста нет, это таблица.
   - *contextual*: среднее скрытых состояний последнего слоя Qwen3 по токенам текста (`output_hidden_states=True`). Те же токены, но после внимания.
   - *e5*: `multilingual-e5-small`, среднее выходов по маске, запрос с префиксом `query: `, абзац с префиксом `passage: `. Энкодер, обученный именно под поиск; что такое энкодер, разберем в лекции 3.

   Для каждого способа посчитать recall@5: долю запросов, у которых правильный абзац попал в пятерку. Правильный абзац это тот, в котором встречается фраза из третьего столбца. Записать `paragraphs.json` и `search.json`. В README таблица recall по трем способам и объяснение, почему они расположились именно так: что добавляет контекст и что добавляет обучение под задачу.

   | № | Запрос | Фраза из правильного абзаца |
   |---|---|---|
   | 1 | Хозяйка вечера несколько дней болела гриппом и утром разослала приглашения | кашляла несколько дней |
   | 2 | Отец говорит, что оба его сына дураки, только один спокойный, а другой беспокойный | покойный дурак |
   | 3 | Богатый и скупой старый князь живет в деревне, его прозвали прусским королем | прозванный прусским королем |
   | 4 | Гости по очереди здоровались с никому не нужной тетушкой | никому не интересной и не нужной тетушки |
   | 5 | Брат удивительно похож на сестру-красавицу, но при этом очень некрасив | поразительно дурен собой |
   | 6 | В гостиную входит невысокий молодой князь с усталым и скучающим взглядом | усталого, скучающего взгляда |
   | 7 | Обедневшая княгиня приехала просить, чтобы ее сына перевели в гвардию | выхлопотать определение в гвардию |
   | 8 | Спор о революции: народ отдал Бонапарту власть, чтобы избавиться от Бурбонов | избавил его от Бурбонов |
   | 9 | Неуклюжий толстый гость по рассеянности взял чужую генеральскую шляпу | треугольную шляпу с генеральским плюмажем |
   | 10 | Мальчика десяти лет отправили за границу с гувернером-аббатом | гувернером-аббатом за границу |
   | 11 | Совет другу: не женись, пока не сделал всего, что мог | не женись до тех пор |
   | 12 | Светлая петербургская ночь, второй час, он едет домой и не может заснуть | бессумрачная ночь |

4. **Внимание.** Загрузить Qwen3 с `attn_implementation="eager"` и `output_attentions=True`, иначе карт внимания не получить.

   а. Для предложения «Врач осмотрел пациента и сказал, что его анализы готовы.» найти слой и голову, в которых местоимение «его» сильнее всего смотрит на «пациента». Нужна строка внимания последнего токена местоимения. Доля на антецедент это сумма весов по токенам слова «пациента». Записать `attention_map.json` и картинку `attention_map.png` с весами по токенам для лучшей головы.

   б. Размывание. Взять инструкцию «Отвечай только по-русски и в конце каждого ответа ставь слово КОНЕЦ.», после нее перевод строки и текст из корпуса такой длины, чтобы весь вход был ровно 128, 512 и 1024 токена (в режиме `--fast`: 64, 256, 768). Для каждой длины посчитать, какую долю внимания последний токен, в среднем по всем слоям и головам, отдает токенам инструкции, и сравнить с долей при равномерном внимании. Первый токен входа в долю не включать: на него модель сбрасывает большую часть внимания при любом тексте, это сток (attention sink), и с ним кривая показывает сток, а не инструкцию. Его долю записать отдельно. Записать `dilution.csv`. В README объяснить, что это значит для промпта, в который кладут много найденных фрагментов: это механизм, который в «Вскрытии №2» виден снаружи.

## Контракт для тестов

`lab02/run.py` запускается из любой папки, без аргументов делает полный прогон, с флагом `--fast` укладывается в десять минут на CPU без GPU. Все пути считаются от папки скрипта. Артефакты в `lab02/artifacts/`; образцы всех файлов из полного прогона лежат в `assignments/02/examples/`, по ним удобно сверять схему, числа будут свои:

| Файл | Содержимое |
|---|---|
| `bpe.json` | `num_merges`, `vocab_size`, `merges` (список пар `[a, b]` в порядке обучения), `stats` с полями `chars`, `words`, `tokens_bpe`, `tokens_per_word`, `compression_vs_chars`, `examples` (слово → список токенов) не меньше чем для `наполеон`, `сказала`, `неудовольствие` |
| `tokens_per_word.json` | `tokenizer`, `vocab_size`, `ru` и `en` с полями `words`, `tokens`, `tokens_per_word`, `words_in_context`; `context_tokens` (4096); `example_ru` (список токенов-подписей) |
| `paragraphs.json` | список абзацев в порядке отбора, каждый `{"id": номер, "text": текст}` |
| `search.json` | `k` (5), `queries`: список объектов `{"query", "answer_phrase", "answer_id", "top": {"static": [...], "contextual": [...], "e5": [...]}}` с номерами абзацев по убыванию близости; `recall_at_k` с полями `static`, `contextual`, `e5` |
| `attention_map.json` | `sentence`, `tokens`, `pronoun_pos`, `antecedent_pos` (списки позиций), `best_layer`, `best_head`, `weights` (строка внимания по всем токенам), `share_on_antecedent` |
| `attention_map.png` | столбики весов по токенам для лучшей головы |
| `dilution.csv` | колонки `context_len`, `instruction_len` (токены инструкции без первого), `share_on_instruction`, `sink_share` (доля на первый токен), `uniform_share`, по строке на длину |

Тесты числам, которые скрипт записал о себе, не верят и пересчитывают, что могут:

- `bpe.json`: слияний не меньше требуемого; применение ваших `merges` по порядку к словам из `examples` дает те же разбиения; `tokens_per_word` и сжатие в правдоподобных пределах.
- `tokens_per_word.json`: на русском токенов на слово больше, чем на английском; счет для английского абзаца совпадает с токенизатором Qwen3; `words_in_context` согласуется с `tokens_per_word`.
- `paragraphs.json` и `search.json`: абзацы отобраны по правилу из части 3 (первые абзацы совпадают с эталонными); `answer_id` для каждого запроса найден по фразе заново; recall пересчитан из `top`; recall у `e5` не ниже порога из эталона. Порядок трех способов не проверяется, он предмет вашего README.
- `attention_map.json`: `weights` это распределение (сумма единица, длина равна числу токенов), `share_on_antecedent` равна сумме весов на `antecedent_pos` и не ниже порога из эталона.
- `dilution.csv`: не меньше трех длин, `uniform_share` равна `instruction_len / context_len`, доля внимания на инструкцию падает с ростом длины.

Если какой-то тест кажется неверным, пишите сразу, не подгоняйте под него результат.

## Бонус

- **Испорченный телефон.** Та же инструкция и тот же наполнитель, что в части 4б, только теперь модель генерирует ответ. Брать чат-версию `Qwen/Qwen3-0.6B`, а не Base: Base-модель инструкциям не обучена, и на ней эффект шумный. Инструкцию подать системным сообщением через шаблон чата, `enable_thinking=False`. Посмотреть, при какой длине контекста слово КОНЕЦ перестает появляться в конце ответа. Это та же кривая из `dilution.csv`, только видимая снаружи.
- **Чей это ключ.** Для слова, у которого два смысла («ключ», «коса», «лук»), взять по два предложения на каждый смысл, снять вектор слова с выхода последнего слоя и показать, что внутри одного смысла векторы ближе, чем между смыслами. Это то самое отличие контекстного вектора от эмбеддинга, только на уровне слова, а не абзаца.
- **Свои запросы.** Добавить десять запросов к абзацам из второй половины отобранных и посмотреть, держится ли порядок способов. Запросы писать своими словами, не цитатами, иначе найдет даже static.

## На что смотрю

Лабораторные являются условием допуска к экзамену. Работа принята, если:

- CI зеленый, артефакты получены вашим скриптом, а не записаны руками;
- BPE написан самостоятельно, без `tokenizers` и готовых реализаций, и вы можете объяснить, почему слияния идут именно в таком порядке;
- в README есть выводы по каждой части, а не только цифры: почему русский дороже, почему три способа поиска дали такой порядок, что происходит с инструкцией в длинном контексте.

На устной проверке попрошу изменить что-нибудь на месте: взять другое местоимение, другую инструкцию, другой слой, другой способ усреднения векторов, и сказать заранее, что изменится. Ассистентом при выполнении пользоваться можно, при проверке нет.
